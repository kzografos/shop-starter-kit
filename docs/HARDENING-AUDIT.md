## Findings

| # | Item | Severity | Existing behaviour (verified) | Root cause | Fix |
|---|---|---|---|---|---|
| A1 | Malformed `:id` on any route → HTTP 500 | **Critical** (availability, log noise) | `GET /orders/not-a-uuid`, `PATCH /admin/staff/abc/role`, … answered `500 Internal server error` with a full Prisma stack in the log; only the notification routes (fixed in `16dcb5b`) answered 400 | Prisma casts the string to `uuid` and raises `P2023`; `GlobalExceptionFilter` treated every non-`HttpException` as 500; no `ParseUUIDPipe` on 14 parameters | `ParseUUIDPipe` on every id parameter (400 at the boundary) **and** Prisma `P2023 → 400`, `P2025 → 404`, `P2003 → 400` in the filter, with fixed messages so no database text reaches the client |
| A2 | `DELETE /newsletter/unsubscribe?email=` unauthenticated | **Critical** (abuse) | Anyone could unsubscribe any address; the welcome mail linked `/unsubscribe?email=…` | Endpoint proved nothing about the caller; no token existed | HMAC-SHA256 token over the lowercased address (key: `JWT_SECRET`), required on the endpoint, embedded in the mail link and read by the page |
| A3 | `POST /orders` not idempotent | **Critical** (money, stock) | Two identical requests created two orders and decremented stock twice; the checkout button only disabled while the request was in flight | No idempotency key anywhere on order creation | `Idempotency-Key` header, scoped to the buyer, stored on the order row inside the creation transaction with a payload digest; unique index; replay returns the original order; different payload → 409 |
| B1 | `/health` checked only Postgres | **Important** (operability) | A Redis outage presented as "everyone gets logged out" while `/health` said `ok`; no container healthcheck on the backend service | Terminus wired with `PrismaHealthIndicator` only; `RedisService` swallowed every error | Redis `PING` indicator with a 2 s deadline; `/health` 503 when either component is down; `healthcheck:` block on the backend service in both compose files |
| B2 | Admin inbox rendered out-of-stock alerts as low-stock; pagination never advanced | **Important** (visible bug) | `n.type === 'OUT_OF_STOCK'` never matched the wire value `out_of_stock`; `data.totalPages` read a key the wire spells `total_pages` | Page declared its own types in the Prisma spelling; `SnakeCaseInterceptor` lowercases enum fields and snake_cases keys | Page uses the shared wire types from `types/index.ts` and compares the lowercase value |
| B3 | `updateStatus` not status-conditional | **Important** (consistency) | Transition table already rejected illegal moves (verified 36/36 pairs); but two concurrent legal moves from the same state both wrote — last write wins, both notifications sent | `prisma.order.update({ where: { id } })` without the status it had checked | `updateMany({ where: { id, status: current } })` inside a transaction with the notification; 409 on a race, same pattern as `cancel()` |
| B4 | Dead code | **Important** (clarity, secrets in the wrong place) | `RefreshToken` model/table (0 rows in the live DB, no code reference), `app/types/database.types.ts` (496 lines, no importer), `pages/confirm.vue`, `pages/admin/products/[id].vue` (redirect stub, no link), `plugins/stripe.client.ts` (`$stripe` never consumed), `nuxt.config.ts` private `runtimeConfig` with Stripe/Resend secrets (no reader), root deps `stripe`/`resend`/`zod`/`@stripe/stripe-js` (no import), `app/package.json` + `app/pnpm-lock.yaml` (stray) | Supabase/serverless-era leftovers | Removed; table dropped by migration; docs updated |
| A5 | Frontend not gated | **Important** (regressions) | CI ran the backend job only; `vue-tsc` and `eslint` were not dependencies; `nuxt typecheck` reported 22 errors, `eslint app` 10 errors; `eslint .` from the root also linted the backend (181 false errors) | Gates never added after the NestJS move | `typecheck` script, `vue-tsc`/`eslint` devDependencies, 32 errors fixed, backend excluded from the Nuxt lint, `frontend verify` CI job |

Additional observations (not changed, recorded for the roadmap): `Profile.role` was typed `'customer' | 'admin'` although roles are module-fed strings since seam 3b (corrected as part of A5); 37 lint warnings remain (33 `vue/html-self-closing` on void elements, 3 `vue/require-default-prop`, 1 `vue/no-v-html`) — warnings do not fail the gate and touching 30+ templates was out of scope.

## Remaining risks after the milestone

- Idempotency keys are only sent by the checkout page; other clients of `POST /orders` (none today) must send the header to get the protection.
- The unsubscribe token is tied to `JWT_SECRET`: rotating the secret invalidates every unsubscribe link in already-sent mails (recipients then see "invalid link" and can subscribe/unsubscribe through the footer again). A dedicated `NEWSLETTER_SECRET` would decouple the two; deferred until rotation is an actual procedure.
- `/health` treats Redis as critical (503). A deployment that wants Redis to be "degraded" rather than "down" must change `HealthController`; the decision and its reason are in the controller comment.
- Frontend behaviour is still verified only by the session harnesses (headless Chrome), which are not in the repository. A frontend test runner remains Phase 4 work.
